# Umbraco backoffice development

Our backoffice customisation consists mostly of block editor previews. Our approach is to customise where it provides a compelling user benefit, but otherwise stick to out-of-the-box features as backoffice customisation can make upgrades more difficult.

Our backoffice components are split between GOV.UK components in `ThePensionsRegulator.GovUk.Frontend.Umbraco\Backoffice` and TPR components in `ThePensionsRegulator.Frontend.Umbraco\Backoffice`.
Both locations are written in [TypeScript](https://www.typescriptlang.org/) using [Vite](https://vite.dev/) as a frontend build tool and [Lit](https://lit.dev/) to ease development of web components. This is the recommended stack for Umbraco backoffice development.

Both projects output scripts to a folder under `wwwroot\App_Plugins` and this is required for Umbraco to register and use the customisations.

You can run `npm run backoffice` at the root of the repo to build all of the backoffice scripts. This must be run after the main .NET build because it relies on a file generated by that build.

To work on either project change to the `Backoffice` folder and run `npm run watch`. For example:

```cmd
cd ThePensionsRegulator.Frontend.Umbraco\Backoffice
npm install
npm run watch
```

This will automatically rebuild files as you work on them in Visual Studio or VS Code, and will refresh the backoffice with your changes. `npm run watch` won't always display detailed errors though, so if the backoffice is not updating try stopping the watcher and run `npm run build` instead to see the error message.
