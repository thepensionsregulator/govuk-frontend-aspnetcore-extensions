# Include client-side files in packages

CSS, JavaScript, image and font files that just need to be requested by the browser can be embedded in the NuGet package just by placing them in the `wwwroot\<package-name>` folder of your project. They will be available as `/<path-within-wwwroot>`.

The paths match because each project file includes `<StaticWebAssetBasePath>/</StaticWebAssetBasePath>`. This is necessary for the projects which include Umbraco backoffice customisation, so it is used for all projects to keep things consistent. Umbraco projects need it because backoffice customisations must be available under `/App_Plugins` for Umbraco to pick them up.

CSS files can be created directly within `wwwroot\<package-name>`, or they can be generated from a SASS file in the `Styles` folder. When generating a CSS file from SASS exclude the generated file from source control. You will need to add a command in `Directory.Build.targets` to compile the SASS to CSS.

## Minifying and caching client-side files

When including a client-side file on a page, always enable client-side caching with a cache-busting parameter that ensures the cache is reset when a new version of the package is published.

### JavaScript files

Configure minification in `bundleconfig.json` at the root of the project. This is processed by the `BuildBundlerMinifier` NuGet package. Then use `asp-append-version="true"` to add a cache-busting parameter:

```razor
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
<script src="/<package-name>/js/my-js-file.min.js" type="module" asp-append-version="true"></script>
```

### CSS files

Create a SASS file in the `Styles` folder, and configure build including minification in `Directory.Build.targets` at the root of the project. The `--style=compressed` switch enables minification. This is processed by Dart SASS, which comes with the `AspNetCore.SassCompiler` NuGet package. Then use `asp-append-version="true"` to add a cache-busting parameter:

```razor
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
<link rel="stylesheet" href="/<package-name>/css/my-css-file.css" asp-append-version="true" />
```

SASS files which reference images can include `_tpr-frontend-version.generated.scss` (or an equivalent file in another project) and then use the `$tpr-frontend-version` SASS variable to append a cache-busting parameter. `_tpr-frontend-version.generated.scss` is generated by `ThePensionsRegulator.Frontend\Directory.Build.targets` and excluded from source control.

```scss
@import "_tpr-frontend-version.generated.scss";

.my-class {
  background: url(/<package-name>/img/my-image.png?v=#{$tpr-frontend-version});
}
```

### Image files

Use `asp-append-version="true"` to add a cache-busting parameter:

```razor
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
<img src="/<package-name>/img/my-image.png" alt="Example image" asp-append-version="true" />
```

### Add a Cache-Control header

If you add files to expected locations they will automatically get a `Cache-Control` header which caches them for a long time.

This is controlled by a class in each project which implements `ThePensionsRegulator.GovUk.Frontend.Caching.IStaticFileCachePolicy`. You can update the class for the project you're working on if you need the header added to other client-side paths.

`ThePensionsRegulator.GovUk.Frontend.Caching.CacheStaticFilesMiddleware` looks at all the `IStaticFileCachePolicy` instances and, if the path of the request matches, it adds the `Cache-Control` header.
